# ZMKにおける &hm (Home Row Mods) と &mt (Mod-Tap) の違い

ZMK Firmwareにおいて、キーを「単押し（タップ）した時は文字」「長押し（ホールド）した時は修飾キー（Ctrl/Alt/Shift等）」として動作させる設定には、標準で用意されている **`&mt` (Mod-Tap)** と、カスタム定義された **`&hm` (homerow_mods)** があります。

これらはどちらも同じ `hold-tap` という挙動エンジンをベースにしていますが、判定アルゴリズム（Flavor）やタイミングの設定が異なります。

`adv360.keymap` で定義されている `&hm`:
```
      hm: homerow_mods {
          compatible = "zmk,behavior-hold-tap";
          label = "HOMEROW_MODS";
          #binding-cells = <2>;
          tapping-term-ms = <200>;
          quick_tap_ms = <175>;
          flavor = "tap-preferred";
          bindings = <&kp>, <&kp>;
      };
```


---

## 1. 比較表

| 項目 | `&mt` (標準のMod-Tap) | `&hm` (カスタム定義のhomerow_mods) |
| :--- | :--- | :--- |
| **判定モード (Flavor)** | **`hold-preferred`** (ホールド優先) | **`tap-preferred`** (タップ優先) |
| **別のキーが同時に押された時** | タイムアウト時間を待たず、即座にホールド（修飾キー）と判定。 | タイムアウト時間内であれば、他キーが押されてもタップ（文字入力）と判定。 |
| **タイムアウト時間 (`tapping-term-ms`)** | グローバル設定（デフォルト値）に依存。 | 個別設定（キーマップ側で `<200>` ms等にチューニング）。 |
| **連打対策 (`quick_tap_ms`)** | なし（連打の2回目がホールドに誤判定されやすい）。 | あり（設定時間内の再打鍵はホールドにならず文字の連打になる）。 |
| **主な用途** | 親指キー、単発で押すキー（Tab/Escape等）への修飾キー同居。 | **Home Row Mods**（アルファベットキーへの修飾キー同居）。 |

---

## 2. 挙動（Flavor）の詳細な違い

ZMKにおける「Flavor」は、キーを押し下げている最中に別のキーが押された際（ロールオーバー入力時）、それを「タップ」とするか「ホールド」とするかを決定するアルゴリズムです。

### 🚨 `&mt` の挙動：`hold-preferred`（ホールド優先）
キーを押したあと、タイムアウト時間（`tapping-term-ms`）が経過する前に他のキーが押された場合、ZMKは**即座に「ホールド（修飾キー）」として判定**します。

* **具体例**：`F` キーに `&mt LSHIFT F` を割り当てている状態で、素早く `F` ➔ `U` とタイプした際、`F` から指が離れる前に `U` が押されると、ZMKは「Shiftが押された」と判断し、画面には `F` `U` ではなく **`U`（大文字のU）** が入力されます。
* **問題点**：タイピング速度が上がると、文字のロール入力（指を滑らせるような入力）がすべて修飾キーの暴発に繋がるため、ホームポジションのキー（A/S/D/F等）に割り当てると入力が著しく不安定になります。

### ✨ `&hm` の挙動：`tap-preferred`（タップ優先）
他のキーが同時に押された場合でも即座にホールドとは判断せず、設定したタイムアウト時間（例：200ms）をフルに待ちます。キーがタイムアウト時間より短く離された場合は、確実に「タップ（文字入力）」として処理されます。

* **具体例**：`F` キーに `&hm LSHIFT F` を割り当てている状態で、指が重なりながら `F` ➔ `U` と素早く入力しても、200ms以内に `F` が離されていれば、意図通り小文字で **`fu`** と入力されます。
* **利点**：タイピング速度が上がっても修飾キーが誤って暴発することがなく、自然なタッチで文字入力を進められます。

---

## 3. 連打設定（`quick_tap_ms`）の有無

キーの連打（リピート入力）を行う際の挙動です。

* **`&mt` (標準)**：
  `quick_tap_ms` が設定されていないため、例えば `BSPC`（バックスペース）と `LSHIFT` を同居させたキーをタタタンと連打した際、連打の途中でホールド判定になってしまい、文字が削除されずにShiftキーとして認識されてしまう問題が発生します。
* **`&hm` (カスタム)**：
  `quick_tap_ms = <175>;` のように設定されています。キーを一度離した後、175ms以内に再度同じキーが押された場合は、ホールド処理をスキップして「前回のタップ（文字入力またはバックスペースなど）の連打」として処理します。これにより、直感的な連打がスムーズに行えます。

---

## 4. 使い分けのガイドライン

* **`&hm` (homerow_mods) を使うべき場所**
  文字入力の主力となるホームポジション周辺のキー（A/S/D/F、J/K/L/; 等）に修飾キー（Ctrl/Alt/Cmd/Shift）を忍ばせる場合。タイピングの快適さを損なわずに修飾キーを配置できます。

* **`&mt` (Mod-Tap) を使うべき場所**
  親指の `Space / Shift` のように、「文字を入力するときは確実に単発で押し、修飾キーとして使う時は他のキーと完全に組み合わせてしっかり長押しする」ような、タップとホールドの役割分担が明確に分かれているキー。
